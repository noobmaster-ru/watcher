# watcher — отслеживание цен Wildberries

Веб-приложение, которое следит за ценами на Wildberries: добавляете артикул или продавца
целиком, а watcher опрашивает WB по расписанию, хранит историю цен и присылает уведомление,
когда цена изменилась или товар пропал из наличия. Тот же код парсинга работает как
MCP-сервер для ИИ-инструментов.

## Что умеет

- **Товар по артикулу или ссылке** — карточка, цена, наличие, характеристики, график истории.
- **Продавец целиком** — весь каталог встаёт под наблюдение, новые товары подхватываются сами.
- **Поиск по фразе** — с честным предупреждением, что WB режет частые запросы.
- **История цен** — за сутки, неделю, месяц, три месяца или всё время.
- **Уведомления** — лента событий в интерфейсе и пуш в Telegram.
- **Пороги срабатывания** — процент и рубли, отдельно снижение и рост, отдельно наличие.
- **MCP-сервер** — шесть инструментов для ИИ: поиск, карточка, цены пачкой, отзывы, продавец, каталог.

## Как устроено

```
packages/wb-core   клиент Wildberries: транспорт, лимитеры, парсеры. Ни БД, ни HTTP
apps/server        Fastify: REST API + планировщик обхода в одном процессе
apps/web           React + Vite: интерфейс
apps/mcp           MCP-сервер поверх того же ядра
```

Три решения, определившие архитектуру:

1. **Запросы к WB идут через системный `curl`, а не через `fetch`.** `card.wb.ru` фильтрует по
   TLS-фингерпринту и отдаёт Node'у 403, а curl проходит. Замена curl на fetch ломает всё
   приложение, хотя выглядит безобидным упрощением.
2. **API и планировщик живут в одном процессе.** WB лимитирует по IP, а не по пользователю,
   поэтому фоновый обход и запросы из интерфейса обязаны стоять в одной очереди с общими
   лимитерами. Запросы живого пользователя обгоняют фоновые.
3. **Цены снимаются пачками по 100 артикулов.** `card.wb.ru/cards/v4/detail` принимает
   `nm=a;b;c`, поэтому тысяча отслеживаемых товаров стоит десяти запросов, а не тысячи.

Отдельно стоит знать про главную ловушку трекера: **у распроданного товара WB не отдаёт объект
цены вообще**. Наивный парсер запишет ноль и отрапортует скидку 100%. Здесь такой случай
превращается в событие «нет в наличии», а цена сохраняется как `null`.

## Быстрый старт

```bash
npm install
cp .env.example .env          # задайте SESSION_SECRET: openssl rand -hex 32
```

Нужен Postgres. Проще всего поднять контейнером:

```bash
docker run -d --name watcher-pg -p 5432:5432 \
  -e POSTGRES_USER=watcher -e POSTGRES_PASSWORD=watcher -e POSTGRES_DB=watcher \
  postgres:16-alpine

npm run db:migrate
npm run dev:server            # http://localhost:3000
npm run dev:web               # http://localhost:5173
```

Фронтенд в разработке проксирует `/api` на сервер, так что открывать нужно `localhost:5173`.

## Проверка

```bash
npm test                  # 60 тестов: логика событий, планировщик, HTTP API, регрессии
npm run check:endpoints   # живы ли шесть эндпоинтов Wildberries
npm run check:live        # сквозной прогон на настоящем WB во временной БД
```

Тесты поднимают настоящий Postgres, скомпилированный в WASM (PGlite) — ни контейнера, ни
установленной базы не требуется. `check:endpoints` — первое, что нужно запустить, если
приложение перестало отдавать цены: WB регулярно меняет версии эндпоинтов.

## Деплой

Рассчитано на **VPS в РФ**: с зарубежных и дата-центровых адресов Wildberries лимитирует куда
жёстче, вплоть до временного бана IP. Если сервер всё же вне РФ, укажите `WB_PROXY` — все
запросы к WB пойдут через российский прокси.

```bash
git clone <репозиторий> watcher && cd watcher
cp .env.example .env
```

В `.env` задайте как минимум:

```ini
SESSION_SECRET=<openssl rand -hex 32>
SITE_ADDRESS=watcher.example.com     # Caddy сам получит сертификат Let's Encrypt
PUBLIC_URL=https://watcher.example.com
POSTGRES_PASSWORD=<свой пароль>
TELEGRAM_BOT_TOKEN=<токен от @BotFather>   # можно оставить пустым
TELEGRAM_MODE=webhook
ALLOW_REGISTRATION=false             # после того, как зарегистрировались сами
```

```bash
docker compose up -d --build
docker compose logs -f app
```

Миграции применяются автоматически при старте контейнера. Проверка живости:

```bash
curl https://watcher.example.com/api/health
```

Ответ показывает состояние базы и каждого хоста WB отдельно: `ok`, `degraded` или `banned`.
Если WB начал ограничивать запросы, в интерфейсе появляется жёлтая плашка — это лимит на
стороне WB, а не поломка приложения.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `WB_DEST` | `-1257786` | Регион доставки. Влияет на цену и наличие, пишется в каждую точку истории |
| `WB_SPP` | `30` | Скидка постоянного покупателя в запросе к карточке |
| `WB_PROXY` | — | HTTP-прокси для запросов к WB |
| `DEFAULT_CHECK_INTERVAL_MIN` | `60` | Интервал проверки цен по умолчанию |
| `SELLER_SYNC_INTERVAL_HOURS` | `12` | Как часто пересинхронизировать каталоги продавцов |
| `SCHEDULER_ENABLED` | `true` | Выключает фоновый обход (удобно в разработке) |
| `ALLOW_REGISTRATION` | `true` | Закрывает регистрацию новых пользователей |
| `HTTP_PORT` / `HTTPS_PORT` | `80` / `443` | Внешние порты Caddy. Меняйте, если порты заняты другим проектом |
| `SITE_ADDRESS` | `:80` | Домен для автоматического TLS либо `:80` без него |

Регион и `spp` записываются в каждую точку истории: без этой пометки цены, снятые для разных
регионов, несравнимы между собой.

## Пользователи при закрытой регистрации

Когда `ALLOW_REGISTRATION=false`, аккаунты заводятся из консоли:

```bash
docker compose exec app node apps/server/dist/scripts/user.js create you@example.com 'пароль'
docker compose exec app node apps/server/dist/scripts/user.js password you@example.com 'новый'
docker compose exec app node apps/server/dist/scripts/user.js list
```

Пароль можно сменить и из интерфейса, на вкладке «Настройки» — при этом все
остальные сессии завершаются.

## MCP-сервер

```bash
npm run build -w @watcher/wb-core && npm run build -w @watcher/mcp
claude mcp add wb --scope user -- node /абсолютный/путь/watcher/apps/mcp/dist/index.js
```

Инструменты: `wb_search`, `wb_product_details`, `wb_product_prices` (до 100 артикулов за
запрос), `wb_product_reviews`, `wb_seller_info`, `wb_seller_products`.

## Лимиты Wildberries

`search.wb.ru` — самый строгий: с зарубежного IP он отвечает `429` почти всегда, с российского
работает, но не любит частых запросов. `card.wb.ru` (цены) и CDN-корзины куда терпимее, поэтому
основная работа трекера идёт через них и лимитов почти не задевает.

Клиент это учитывает: у каждого хоста своя пауза между запросами, при серии `429/403` хост
закрывается на растущий таймаут, а запросы из интерфейса обгоняют фоновый обход в очереди.

## Происхождение

Логика парсинга выросла из [wb-mcp-server](https://github.com/Jerardx/wb-mcp-server). Оттуда
перенесены таблица шардов CDN, выбор хоста отзывов по CRC16/ARC и обход TLS-фильтра через curl —
детали, которые проще сохранить, чем переоткрыть.
